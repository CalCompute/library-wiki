# NERSC user account policies (web)

## Citation

National Energy Research Scientific Computing Center (NERSC), Lawrence Berkeley National Laboratory. "Account Policies." NERSC Documentation, date not stated. https://docs.nersc.gov/accounts/policy/. Copy: [`raw/web/2026-11-12 NERSC user account policies.md`](../../raw/web/2026-11-12%20NERSC%20user%20account%20policies.md) (original: `.html` beside it). Read 2026-11-12.

## Bottom line

- The page gives the life of a NERSC user account: request, vetting, PI approval, continuation and deactivation.
- An account must belong to an active project. NERSC vetting "generally takes less than a week".
- NERSC disables a user who shares a password. After a project ends, the user can log in for 14 days but cannot run jobs. Then the account has 60 days of "data-access only" and 30 more days before deactivation.

## Background

This page is in the NERSC technical documentation. It says that its policies "originate from a number of sources, such as DOE regulations and DOE and NERSC management". It links to the [NERSC Appropriate Use Policy (web)](NERSC%20Appropriate%20Use%20Policy%20%28web%29.md) and the [NERSC Code of Conduct (web)](NERSC%20Code%20of%20Conduct%20%28web%29.md). The page gives no date. It names "Allocation Year 2027" for a new rule.

## Key claims

- One person per account: "This username and its associated password and MFA may be used by a single individual only." (User Account Ownership, Password, and MFA Policies)
- Sharing: "NERSC will disable a user who shares any one of their passwords with another person." (User Account Ownership, Password, and MFA Policies)
- Creation: "Account requests must be associated with a project." "Once the account request is received, NERSC vets the prospective user. This process generally takes less than a week, though it could take longer in some cases." (Account Creation)
- PI approval: "Following NERSC's vetting, the project PI must approve the user to join the requested project." (Account Creation)
- Continuation: "NERSC accounts are tied to project allocations. For an account to remain active, it must be associated with an active project." The user "must agree to the NERSC Appropriate Use Policy and Code of Conduct". (Account Continuation)
- Deactivation steps: "there is a 14-day period during which the user can still log onto computational systems but cannot submit jobs. The user account then enters a 60-day "data-access only" state". "Following that period, the account becomes "expired", and after 30 more days, the account is deactivated and its password and MFA token are deleted." (Account Deactivation Process)
- Short-term members: "PIs have the option to set an expiration date for project membership (e.g., for a summer intern who will not continue after the internship)." (Account Deactivation)

## Evidence and method

This is a documentation page of rules. It gives time periods for vetting and for deactivation. It has no data on the number of accounts or on how long vetting takes in practice.

## Limits

- The page does not say what the NERSC vetting checks.
- It does not say when vetting takes longer than a week.
- It does not give a date of publication or revision.
- It does not say how NERSC decides to re-enable a user who shared an account. It says only that "NERSC will then determine if the user should be re-enabled".
